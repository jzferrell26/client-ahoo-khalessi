## Warnings (should fix)

- [ ] **Set both production webhook secrets before declaring the website live** - `README.md:57-76`

  The server routes Get My Options and AVM submissions to separate environment variables. The code intentionally returns 503 when the selected value is absent, so a merged build without `GHL_GET_MY_OPTIONS_WEBHOOK_URL` and `GHL_AVM_WEBHOOK_URL` cannot complete both intake paths. Suggested: set both server-only values in the production website host, deploy, and submit one controlled test through each form.

- [ ] **Add Bobby's NMLS only after CTC confirms it** - `src/routes/index.tsx:745-751`

  Bobby's requested card, phone, title, photo, and bio are present, but the plan also calls for his NMLS. No verified number was present in the supplied sources, so the implementation correctly avoids inventing one and leaves the field unset. Suggested: obtain the number directly from CTC or an approved licensing record, add it to the card, and include it in the compliance review.

## Suggestions (consider improving)

- [ ] **Add automated tests for intake routing and failure branches** - `src/routes/api.lead.ts:38-92`

  The build, type check, lint check, and static security review pass, but the repository has no automated test harness for the new route. Tests should cover each `lead_kind`, malformed JSON, the 16 KiB limit, missing webhook configuration, and a non-2xx HighLevel response.

- [ ] **Add platform-level abuse protection before paid traffic scales** - `src/routes/api.lead.ts:38-92`

  Schema validation and the request-size cap constrain individual requests, but they do not limit request volume. Suggested: add host-level rate limiting or Turnstile before significant mailer or advertising traffic reaches the public forms.
